----- REPLY:
The issue is that `Segment.split_cells` does not handle negative `cut` values correctly. When `cut` is negative, the current implementation in `_split_cells` calculates a `pos` that may lead to unexpected slicing behavior (e.g., `s.split_cells(-1)` for `"AA"` returning `(Segment('A'), Segment('A'))` instead of `(Segment(''), Segment('AA'))`). The fast path for single-cell width characters also fails to handle negative `cut` values, allowing them to reach the slicing logic which treats them as indices from the end of the string.

FILES: rich/segment.py:172-181 (split_cells) and rich/segment.py:127-128 (_split_cells)

CAUSE: `cut` values are not clamped to a minimum of 0, leading to incorrect string slicing when negative values are passed.

FIX: Add a check to clamp `cut` to 0 at the beginning of `split_cells` and/or `_split_cells`.
