----- REPLY:
The issue asks for a re-implementation of `on_event` in FastAPI to maintain compatibility with future Starlette versions where the native `add_event_handler` might be removed or changed, while keeping backwards compatibility for FastAPI users.

Currently, `FastAPI.on_event` delegates to `self.router.on_event`, and `APIRouter.on_event` calls `self.add_event_handler(event_type, func)`. Since `APIRouter` inherits from `starlette.routing.Router`, `add_event_handler` is a Starlette method. To decouple from Starlette's `add_event_handler`, FastAPI needs to manage these event handlers internally (e.g., in a list) and trigger them using the `lifespan` mechanism.

FILES:
- `fastapi/routing.py`: Modify `APIRouter` to store event handlers in its own lists (`on_startup` and `on_shutdown`) and implement `add_event_handler` to append to these lists.
- `fastapi/applications.py`: Ensure `FastAPI` correctly handles these router event handlers during its lifespan.

CAUSE: Dependence on Starlette's `Router.add_event_handler`, which is being deprecated/changed in Starlette.

FIX: 
1. Add `on_startup: list[Callable]` and `on_shutdown: list[Callable]` to `APIRouter.__init__`.
2. Re-implement `APIRouter.add_event_handler` to store handlers in these lists instead of calling `super().add_event_handler`.
3. Update the application's lifespan logic to execute these handlers.

REPRO: none (this is a compatibility architectural change)
