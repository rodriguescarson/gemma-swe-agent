CAUSE: `Dependant.cache_key` includes `self.security_scopes`, which are inherited from the caller in `get_dependant`. If a dependency doesn't use scopes itself but is called by one that does, it gets a different cache key, causing redundant calls.
FIX: Modify `Dependant.cache_key` to only include `security_scopes` if the dependency actually requires them (i.e., it uses `SecurityScopes` or declares scopes).
REPRO: none (the simple case passed because `SecurityScopes()` without arguments might be resolving to empty scopes, or I need a more complex scope set)
