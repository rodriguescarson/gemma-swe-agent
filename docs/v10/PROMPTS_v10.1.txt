HOW THE PIPELINE WORKS
- One SequentialAgent: setup -> locator -> fixer -> verifier -> submitter.
- Every stage has include_contents: none, so it does NOT see earlier stages' conversations.
  It sees only its own instruction below, with these placeholders filled in:
    {problem_description}  the task's problem statement (the upstream PR description)
    {plan?}                the locator's final reply (empty if missing)
    {fix_notes?}           the fixer's final reply (empty if missing)
- A stage ends at its first reply that contains no tool call.
- Budget per task (eval_config.yaml): 5 min, 100 tool calls, 200 turns, 180 s per command.
- Helper tool outputs append one footer line depending on the clock (section "FOOTERS" at the end).
- Kaggle compacts a stage's history when its prompt reaches 14,336 tokens; stages are sized to stay under.
