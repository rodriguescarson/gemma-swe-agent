0. Mechanism (code, installed stack swegemma 0.2.11 / google-adk 1.36.1; pinned by
   tests/test_v13_rich_solve.py::test_jsonesc_states_the_escapes_the_installed_stack_really_shows)
   swegemma's tool wrappers return dicts (tools/base.py parse_tool_response); ADK's LiteLLM adapter json.dumps the dict once
   (lite_llm.py _safe_json_serialize, ensure_ascii=False). So a file's backslash reaches the model as two characters, a double
   quote as \" and a newline as \n. The host confirmed the same for the scorer after the 09-30 wheelhouse: "Tool output is
   JSON-encoded once, and edit_file has an unescape fallback" (research/2026-10-04_kaggle_scan.md). v13 dropped edit_file and
   with it that fallback: its template matches the old block exactly.

4. Risk (inferred)
   The line is 75 Gemma tokens on every call. It could make the model under-escape where a Python string in the file really
   holds two backslashes; the rule says one backslash per pair shown, which is the exact decoding, so a correct reading is
   unaffected. No run of the 32 solved tasks is known to depend on writing an escaped form.
