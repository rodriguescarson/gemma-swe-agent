## Problem

- The issue is a maintainer PR titled "Fix ZWJ and edge cases"; the body is "Fixes #3947" and "Fixes #3950" (links only).
- Two bugs in `rich/cells.py`, both left by the grapheme rewrite (rich_3930):
  1. `_cell_len` calls `next(iter_characters)` after a zero-width joiner (U+200D); a string that ends in a joiner raises `StopIteration`.
  2. `get_character_cell_size` measures C0 and C1 control characters as 1 cell. Before the rewrite they were 0: the old `rich/_cell_widths.py` began `(0, 0, 0), (1, 31, -1), (127, 159, -1)` and `-1` was read as 0 (`git show 0f2f51b872:rich/_cell_widths.py`, measured). The new tables have no `-1` entries, so the base code's `return 0 if width == -1 else width` branch is dead.
- Gold: 2 hunks, +16/-10. A guard `if codepoint and codepoint < 32 or 0x07F <= codepoint < 0x0A0: return 0` (the old table's ranges), a cleaned-up binary search, and an index-based loop in `_cell_len` that skips the character after a joiner only if there is one.
- FAIL_TO_PASS (2), both in `tests/test_cells.py`:
  - `test_zwj`: `cell_len("") == 0`, `cell_len("‍") == 0`, `cell_len("1‍") == 1`, `cell_len("1‍2") == 1`. Base: `StopIteration`.
  - `test_non_printable`: `cell_len(chr(i)) == 0` for `i` in 0..30. Base: `assert 1 == 0` at `"\x01"`.
- PASS_TO_PASS: 54.

## Root cause

- **Taxonomy: WRONG_SEMANTICS (partial) + HIDDEN_SPEC part.** The stated bug (the joiner) is fixable and was fixed 8 times. The second F2P requires restoring a behaviour the rewrite dropped (control characters are 0 cells), which "edge cases" does not name. On the current line (b1024) there is also a time failure: 14 calls, long single-probe turns, no edit.
- **Feasible in 5 minutes: no** (maybe at best). The joiner half is easy; the control-character half needs the agent to suspect a regression of the recent rewrite and compare with the pre-rewrite table, at 3-4 extra calls, with nothing in the issue pointing there.
- **General levers** (no task content), none built:
  1. **Regression check against the pre-rewrite version.** When the code to fix was rewritten in recent commits, run a few edge inputs through the previous version (`git show <commit>^:<path>`) and keep behaviour the rewrite lost. It would surface `(1, 31, -1)` here and the `return 1` past the table in rich_3944 (whose title never points at this module). Not built: it costs several calls on every task and nothing measured says the model would take the step; one candidate in the 74 where it is the missing piece.
  2. **Edge-input sweep** already exists as `submissions/v13_edge_sweep` (origin/forty-two-cloud-rich): calling the fixed function on empty input and the special item alone, first, last and repeated would catch the trailing-joiner crash, but it has no reason to try control characters, so it would not flip this task (inferred from its rule text).
  3. **Batch probes** (b1024): five separate one-line probes at ~35 s each; one script with all inputs would have cost one turn. The thinking budget, not the tool, set the price (TIMING.md section 12).
