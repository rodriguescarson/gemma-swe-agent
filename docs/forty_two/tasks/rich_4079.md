# rich_4079: Inline code inside Markdown table cells loses its highlighting

Sources. Measured numbers come from `docs/forty_two/ground_truth/rich_4079.json` (`gt_rich.py` and `trace_rich.py` in
`docs/forty_two/ground_truth/rich_tools/`). Box rows are in `eval/a6000/results/<run>/results.jsonl` and L4 rows in
`eval/kaggle/<run>/results.jsonl`. "Inferred" marks claims no command checked.

## Problem

- The issue is a maintainer PR: "Inline table code / Fixes https://github.com/Textualize/rich/issues/4038". That is the whole text.
- Bug: in a Markdown table cell, `TableDataElement.on_text` wraps the incoming text and then calls `text.stylize(context.current_style)`. That paints the cell style over a `Text` that the inline-code lexer has already highlighted, so the syntax colours are lost.
- Gold: `rich/markdown.py`, 1 hunk, +4/-3. Plain `str` is appended with the current style; an already-built `Text` is appended untouched (`append_text`).
- FAIL_TO_PASS (1): `tests/test_markdown.py::test_inline_code_in_table_cells`. It renders `` | `print('hello');` | `` with `inline_code_theme="monokai"` and `inline_code_lexer="python"`, and asserts the exact ANSI output, which includes the monokai foreground `38;2;248;248;242` on background `48;2;39;40;34`.
- PASS_TO_PASS: 7 tests in `tests/test_markdown.py`.

## Root cause

- **Taxonomy: UNDERSPECIFIED_ISSUE, which leads to WRONG_LOCATION.** The title is three words and a link. "Table" pulls 4 of 6 runs into `rich/table.py`. The two runs that reached the gold hunk (p4, v7c) then made a **WRONG_SEMANTICS** no-op change, keeping the `stylize` call that causes the bug.
- **Correction to the old diagnosis (ENV_BLOCKED_LOCAL):**
  - The environment problem is real: gold fails under Pygments 2.21.0 and passes under 2.20.0 (measured).
  - But none of these six box patches passes under 2.20.0 either. Their failures are the agent's, not the environment's.
  - The old claim that "v6/v7 output identical to gold" does not hold for the current runs.
- **Feasible in 5 minutes: maybe.** Measured: 1 of 12 L4 runs solved it, in 231 s and 40 calls; a test run costs 0.3 s.
- **General levers:**
  1. **Title-to-identifier grep.** Join adjacent title words as `snake_case`/`CamelCase` and `git grep` them before the semantic search. `inline_code` finds only `rich/markdown.py` here (measured). The old diagnosis proposed the same lever for 3935 and 4077.
  2. **Differential repro for "X inside Y" bugs.** Render the same input outside and inside the container (a paragraph against a table cell) and diff. The difference names the mechanism, here a style painted over highlighted text, in one call.
  3. **Budget discipline.** Stop searching after about 20 calls and reserve 5 for edit, test and submit. b1024 spent its 40th call on its first edit. The harness's `budget_warning` appears only at 10 remaining calls; a prompt rule or helper can enforce the earlier stop.
  4. **Identical-repro breaker** (as in 3777 and 3278). p4 ran 26 and v7d 46 near-identical repro commands.
