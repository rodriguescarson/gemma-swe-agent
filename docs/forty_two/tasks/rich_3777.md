## Problem

- The issue is a maintainer PR, "TTY_INTERACTIVE env var".
  - It adds a `TTY_INTERACTIVE` variable to disable progress bars and spinners in CI.
  - It says the change "adds to the new `TTY_COMPATIBLE`".
  - It names only the `=0` behaviour: "`TTY_INTERACTIVE=0` will remove superfluous animations".
- Gold touches `rich/console.py` and `rich/diagnose.py` in 3 hunks, +12/-1.
  - In `Console.__init__`, when `force_interactive is None`, `"0"` forces `is_interactive` False and `"1"` forces it True; any other value auto-detects.
  - The rest is an import reshuffle and the env name added to `diagnose.report`.
- FAIL_TO_PASS (1): `tests/test_console.py::test_tty_interactive`. With a `BytesIO` file (not a terminal):
  - the default is not interactive;
  - `TTY_INTERACTIVE="1"` **is** interactive;
  - `TTY_COMPATIBLE="1"` is interactive;
  - `TTY_INTERACTIVE="foo"` auto-detects (not interactive).
- PASS_TO_PASS: 98 tests in `tests/test_console.py`.

  - The `1` case is not stated. It follows from the sibling the issue names. At base, `Console.is_terminal` parses `TTY_COMPATIBLE` as `"0"` → False and `"1"` → True, with other values falling through (`rich/console.py:951-957`).

## Root cause

- **Taxonomy: WRONG_SEMANTICS, half of a convention.** The runs implemented only the `0` value of a variable whose `0`/`1` convention is defined by the sibling the issue names. The current line adds a self-inflicted regression and no test run (b1024). The v7 line adds repeat loops (v7d) and a verifier stuck rewriting repros (v7c).
  - This agrees with the old diagnosis ("semantics detail + edit tool").
  - Correction: the `1` case is not hidden. The base code and `test_tty_compatible` show it.
- **Feasible in 5 minutes: yes.** Measured: v0-think solved it on the box in 289 s; 4 of 12 L4 runs solved it in 58 to 305 s; a test run costs 0.3 s.
- **General levers:**
  1. **Mirror the named sibling.** When an issue says a change "adds to", "is like" or "mirrors" an existing option, `git grep` that option in the source **and in tests/**. Implement the same value set, and write the repro by copying its test with the new name. One grep and one read, about 10 s of model time.
  2. **Run the edited module's test file once before submitting.** It takes 0.3 s here. b1024 would have seen 96 failures from a property without a setter.
  3. **Identical-command breaker.** Refuse or flag the third identical command, for example "this exact command already returned exit 1 twice". v7d spent about 55 s on 46 identical greps. Helper scripts or a prompt rule can enforce this in any repo.
  4. **Cap repro rewrites.** If two repro scripts do not settle the question, run the existing test file and submit. v7c used about 200 s on 9 repros.
