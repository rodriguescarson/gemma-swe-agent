## Problem

- The issue is a maintainer PR titled "fix for padding width"; the body is only "Fixes https://github.com/Textualize/rich/issues/3871". No identifier, example or file.
- Bug: `Table._get_padding_width` (`rich/table.py:699`), which adds padding to each column's measured width, ignores `pad_edge`. The renderer (`_get_cells`' `get_padding`) drops the left padding of the first column and the right padding of the last when `pad_edge` is False (the default for `Table.grid`). So the measured width is 1-2 cells wider than what is drawn, and the slack shows up as extra spaces.
- Gold: `rich/table.py`, 5 hunks, +13/-3 (two of them blank lines). `_get_padding_width` gets the `pad_edge` rule and a rewritten `collapse_padding` branch.
- FAIL_TO_PASS (2):
  - `tests/test_table.py::test_padding_width` (new): `Table.grid(padding=(0, 1))` with three `width=3` columns must export `"aaa aaa aaa\n"`; base gives `"aaa  aaa aaa \n"`.
  - `tests/test_columns.py::test_render`: the test patch updates the expected `Columns` rendering (built on `Table.grid`) by one space in the "fixed width" block.
- PASS_TO_PASS: 20 tests across the two files.
