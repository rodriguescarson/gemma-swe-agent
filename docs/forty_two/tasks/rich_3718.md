## Problem

- The issue is a maintainer PR titled "fix(panel): fix title missing panel background". The body says the PR "really just reverts the change in 7a38204" and gives "Fixes #3569". It names no file and no test.
- Bug: `Panel(style="on blue", title=Text(..., style="red"))` renders the title (and subtitle) without the panel's `on blue` background. They are stylized with `partial_border_style` (the border style only) instead of `border_style = style + border_style`.
- Gold: `rich/panel.py`, 3 hunks, +3/-4. It drops the `partial_border_style` variable and changes **both** `title_text.stylize_before(...)` (line 209) and `subtitle_text.stylize_before(...)` (line 258) to `border_style`.
- FAIL_TO_PASS (1): `tests/test_panel.py::test_title_text_with_panel_background`. It renders a 50-column truecolor panel with `style="on blue"`, a red title and a bold magenta subtitle. It asserts the exact ANSI string, which needs `\x1b[31;44m title` **and** `\x1b[1;35;44m subtitle`: both carry background 44.
- PASS_TO_PASS: 12 tests in `tests/test_panel.py`, including the second new test `test_title_text_with_border_color`, which already passes at base.

## Root cause

- **Taxonomy: WRONG_SEMANTICS (partial, sibling site missed)** in p4 and v7c. The current line adds **EDIT_TOOL_FAILURE** (malformed tool-call arguments, b1024) and a **WRONG_LOCATION / edit loop** (v7, v7d).
  - The old diagnosis called this "contested: location within file + no test run". That stands, with two corrections:
    - The two runs that edited the right hunk did run tests, but only the existing test file, which cannot fail.
    - The deciding detail is the sibling subtitle line.
- **Feasible in 5 minutes: yes.** Measured: v0-think solved it on the box in 207 s, 9 L4 runs solved it in 51 to 305 s, and a test run costs 0.3 s.
- **General levers** (no task content):
  1. **Fail-first check.** Before editing, write a 3-line assert of the issue's symptom and run it to a failure; after editing, rerun it. Passing existing tests is not evidence when they passed before the edit too. This is what separated v0-think from p4 and v7c.
  2. **Sibling sweep after each edit.** After replacing an expression, `git grep -n "<old expression>" -- <edited file>`. If it still occurs on a parallel branch (title/subtitle, get/set, load/loads), apply the same edit there.
     - v12's prompt already states the rule, but no run checks it.
     - A helper edit script could print "N other lines still contain `<old>`" automatically.
  3. **Malformed-call breaker.**
     - When a tool reply says mandatory parameters are missing, the next edit must use a different form: `python3 - <<'EOF'` with `str.replace` on the file, or `write_file` for a short file.
     - The bundle should also stop sending `edit_file` with temperature 1.0. Measured over all 74 traces: malformed calls occur only in the two bundles that expose `edit_file` (b1024: 84 in 11 tasks; v0-think: 17 in 5 tasks). The four helper-script bundles have 0.
     - That they are caused by temperature 1.0 rather than by the tool itself is inferred, not tested.
  4. **History lookup for "revert"/"regression since" issues.** Snapshot hashes are rewritten, so search by content: `git log -S <identifier> -- <file>` and `git show <hit>`. Measured: this finds the reverted commit here.
