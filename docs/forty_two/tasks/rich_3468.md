## Problem

- The issue is a maintainer PR: "handle broken pipe / Handle BrokenPipe exceptions / Fixes https://github.com/Textualize/rich/issues/1591".
- Bug: when stdout is a closed pipe, `Console._check_buffer` raises `BrokenPipeError`. Python then fails again on its final stdout flush, exits with status 120, and prints "Exception ignored ... BrokenPipeError" to stderr.
- Gold changes `rich/console.py` in 4 hunks, +36/-6. Two hunks are reformatting. The fix itself:
  - `_check_buffer` calls a new `_write_buffer` inside `try`.
  - On `BrokenPipeError` it calls a new `on_broken_pipe()`, which sets `quiet`, `os.dup2`s devnull onto stdout and raises `SystemExit(1)`. This is the recipe from Python's "Note on SIGPIPE".
- FAIL_TO_PASS (1): `tests/test_console.py::test_brokenpipeerror`. It runs `python -m rich | head -1` through `subprocess` and asserts `returncode == 1`.
- PASS_TO_PASS: 97.
- **Environment detail (measured).** The test returns early, and passes vacuously, when `which python` fails. My first run had no venv `python` on PATH and found 0 FAIL_TO_PASS. With the venv's `bin` first on PATH, as in the sandbox, it fails at base with `assert 120 == 1`. `gt_rich.py` now always puts the venv first on PATH.

## Root cause

- **Taxonomy: HIDDEN_SPEC (exit-status contract) plus WRONG_SEMANTICS.**
  - The test pins exit status 1, which the issue does not state.
  - Before that, 4 of 5 editing runs (including v13) did not stop the reported symptom at all, and none checked the real command.
  - The old diagnosis (HIDDEN_SPEC, maybe; "except BrokenPipeError: return gives exit 120") stands. The new evidence is that the symptom check is one shell pipeline and it is red on 4 of 5 patches.
- **Feasible in 5 minutes: maybe (low).** The fix is about 15 lines and the test takes 1.1 s. The exit status 1 still has to come from the model's knowledge of Python's SIGPIPE recipe, because nothing in the repository gives it. 0 of 19 runs solved it.

## SOLVE

- **Lever: reuse `submissions/v13_redfirst`** (fastapi agent, commit 02d63d09 on origin/forty-two-fastapi-solve).
  - A check derived from the issue must be red before the first edit and green after.

  - It does not supply the exit status 1. Expectation: low.
- **Not built:** a rule that names the SIGPIPE recipe or an exit status. That would be this task's answer in the prompt.
