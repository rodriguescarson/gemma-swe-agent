## Problem

- The issue is a maintainer PR titled "preserve newlines"; the body is only "Fixes https://github.com/Textualize/rich/issues/3577".
- Bug: `AnsiDecoder.decode` in `rich/ansi.py` iterates `terminal_text.splitlines()`, which drops a trailing newline (and so `Text.from_ansi("Hello\n")` has plain text `"Hello"`). Measured at base with the same input through every user-level entry point: `console.print`, `Text(...)`, `Text.from_markup` and `markup.render` keep `"Hello\n\nWorld\n"`; only `Text.from_ansi` returns `"Hello\n\nWorld"`.
- Gold: `rich/ansi.py`, 1 hunk, +3/-3: split with `re.split(r"(?<=\n)", ...)` and strip the newline from each piece (plus a docstring line).
- FAIL_TO_PASS (4), all in `tests/test_ansi.py`: `test_decode` (an extra empty `Text("")` line), `test_decode_example` (an extra final `\n`), `test_decode_issue_2688[...]` (the decoded text keeps its trailing `\n`), and the new `test_decode_newlines` (12 `Text.from_ansi(...).plain` round trips such as `"\n"`, `"Hello\n\n"`, `"\nHello\nWorld\n\n"`).
- PASS_TO_PASS: 20.

## Root cause

- **Taxonomy: UNDERSPECIFIED_ISSUE -> WRONG_LOCATION.** "Preserve newlines" does not say where newlines are lost; the only entry point that loses them is the ANSI decoder, and no run tried it. On the thinking-off line the joined-title search returned nothing and the pipeline looped on it.
- **Feasible in 5 minutes: maybe.** For: a search for the newline-removing operation lists the call site first or second (measured); the fix is one token and passes 24/24 (measured); tests cost 0.5 s. Against: 0 of 18 runs; the model must go from "lost" to "what removes it" and must pick a split that keeps the final empty line.
- **General levers** (no task content):
  1. **Something lost: search for what removes it.** When the issue says something is lost or not preserved, search for the operations that cut, trim or deduplicate it and check each hit. Built as `submissions/v13_lost_search` (below).
  2. **Identical-command breaker** (already proposed in the rich dossiers): p4 and v7 sent the same empty search about 60 times. It also bears on `v13_title_ident` (rich_3935): a joined title that matches nothing must not be retried.
