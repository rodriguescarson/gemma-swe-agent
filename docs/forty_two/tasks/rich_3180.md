# rich_3180: Double-width (CJK) characters disappear when wrapping

Sources. Measured numbers come from `docs/forty_two/ground_truth/rich_3180.json` (`gt_rich.py` and `trace_rich.py` in
`docs/forty_two/ground_truth/rich_tools/`). Box rows are in `eval/a6000/results/<run>/results.jsonl` and L4 rows in
`eval/kaggle/<run>/results.jsonl`. "Inferred" marks claims no command checked.

## Problem

- The issue is a contributor PR, "Fix double-width characters disappearing when wrapping".
  - CJK characters vanish when the fold point falls inside a double-width character.
  - It quotes the intended browser-like rule: move to a new line, and fold only words longer than a whole line.
  - It mentions "Fixes #3176".
- Gold: 2 files, 4 hunks, +89/-38.
  - `rich/cells.py`: `chop_cells(text, width)` is rewritten to walk the text **forward**, with the `position` argument dropped.
  - `rich/_wrap.py`: `divide_line` is restructured around `cell_offset`/`remaining_space`, and docstrings are added.
- FAIL_TO_PASS (4):
  - `tests/test_cells.py::test_chop_cells`: `chop_cells("abcdefghijk", 3) == ["abc","def","ghi","jk"]`.
  - `test_chop_cells_double_width_boundary`: `"ありがとう"` at width 3 gives one character per line.
  - `test_chop_cells_mixed_width`: `"あ1り234が5と6う78"` gives `["あ1","り2","34","が5","と6","う7","8"]`.
  - `tests/test_text.py::test_wrap_cjk_mixed`: `"123ありがとうございました"` wrapped at 8 gives `"123あり\nがとうご\nざいまし\nた\n"`.
- PASS_TO_PASS: 110 tests in `tests/test_cells.py` and `tests/test_text.py`, including 3 new `test_wrap_*` tests that already pass at base.

## Root cause

- **Taxonomy: WRONG_SEMANTICS.** The defect is visible as reversed output from a 1-line probe of `chop_cells`.
  - The runs instead reasoned about `divide_line` arithmetic in very long thinking turns (no fix), or patched `_wrap.py` (p4).
  - The one run that fixed `chop_cells` (v7d) also changed `divide_line` and broke 7 tests it never ran.
  - Part of the F2P set (forward order from `chop_cells`) is a contract only the tests state, so this has a HIDDEN_SPEC component. It is recoverable because reversed lines are obviously wrong.
- **Correction to the old diagnosis.** It said WRONG_SEMANTICS, "rewrite borderline, feasible no". Measured: a one-token change (drop `reversed`) passes all 114 target tests in the clean environment, and the same change resolved on Kaggle (g4-l4-v4). The gold's +89/-38 rewrite is not required.
- **Feasible in 5 minutes: yes.** Measured: a 1-token fix, a 0.3 s test, and 1 of 12 L4 runs succeeded in 140 s. The difficulty is noticing the reversal, not the time.
- **General levers:**
  1. **Probe each function in the call chain on a tiny input and print its output** before reasoning about the caller: `python3 -c "from m import f; print(f('abcdefghijk', 3))"`. Reversed, duplicated or missing elements are then visible directly. This beats reasoning in a thinking turn of 80 to 150 s.
  2. **Regression gate**: run the existing test files of every edited module before submitting. v7d would have seen 7 failures in 0.2 s and could have reverted its `_wrap.py` part.
  3. **Bound thinking per turn.** Thinking turns of 78 to 181 s recur in v0-think (budget 4,096) and b1024 (budget 1,024, including a 78 s text-only turn) across rich_3180, 3278 and 4079. A prompt rule ("if you cannot decide in a few sentences, run a probe") or a lower thinking budget for exploration turns trades thinking for observation.
