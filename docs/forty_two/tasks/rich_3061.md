## Problem

- The issue is a maintainer PR, "Extend tabs with styles": "The `Text.extend_tabs` method was previously not taking in to account the spans ... it would replace tabs with unstyled spaces. This resolves that issue by extending the style(s) on the tab to cover the new space characters". It includes a screenshot.
- The method is actually named `expand_tabs`. `extend_tabs` does not exist anywhere in the tree.
- Gold rewrites `expand_tabs` in `rich/text.py` (1 file, 13 hunks, +67/-24):
  - adds a new public method `Text.extend_style(spaces)`;
  - rebuilds the text line by line, measuring with `cell_len`;
  - extends each tab's styled span by the inserted spaces;
  - changes `tab_size` handling.
- FAIL_TO_PASS (12):
  - `tests/test_text.py::test_extend_style`, which calls the new method `Text.extend_style`. That name appears only in the test.
  - 10 cases of `test_tabs_to_spaces_spans`, which pin the exact resulting span lists:
    - no empty-style spans (for example `"\t"` gives `[]`);
    - styles stretched over the spaces (`[bold]foo\tbar` gives `Span(0, 4, 'bold')`);
    - tab stops measured in cells: `"💩\t💩"` at size 8 gives 6 spaces, not 7.
  - `tests/test_panel.py::test_render_size`, which depends on the new tab handling.
- PASS_TO_PASS: 100.

## Root cause

- **Taxonomy: HIDDEN_SPEC.** This confirms the old diagnosis.
  - A new public method name (`extend_style`) exists only in the test.
  - Most of the F2P set pins exact span lists and cell-width tab stops that the issue never states.
  - All seven runs implemented the stated idea and still pass 0 of 12 F2P tests.
- **Feasible in 5 minutes: no.** Measured: 0 of 19 runs (7 box, 12 L4) passed even one F2P case beyond what is stated. The `extend_style` test cannot pass without the name.

## SOLVE

- **No bundle.** No rule that applies to any Python repository can produce an API name or a span layout that only the hidden tests define. `docs/forty_two/queue/rich_3061.json` records `"bundle": null` with this reason.
- A smaller general observation, not built: the issue names a method that does not exist (`extend_tabs` vs `expand_tabs`), and v13 spent 17 s on 5 greps for it. Another agent's `v13_title_ident` and `v13_lost_search` bundles (origin/forty-two-rich-b) target name-to-identifier search. That saves seconds, not this task.
