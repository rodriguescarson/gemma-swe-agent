# rich_3471: exception in `Text.append_tokens` (control codes)

Sources. Measured numbers are in `docs/forty_two/ground_truth/rich_3471.json`. That file was written by three scripts in `docs/forty_two/ground_truth/rich_tools/`: `gt_rich.py` (bounded pytest), `trace_rich.py`, and `edge_sweep_rich.py`. The edge sweep passes the same strings through `Text.append` and `Text.append_tokens` and prints at width 40, at base, under gold and under three box patches, with each call bounded to 10 s; it is stored under `edge_sweep`. Box rows (including p4_v13) are in `eval/a6000/results/<run>/results.jsonl`, and L4 rows are in `eval/kaggle/<run>/results.jsonl`.

## Problem

- The issue is a maintainer PR: "Fixed exception in append_tokens / Fixes https://github.com/Textualize/rich/issues/3014". That is all it says.
- Bug: `Text.append_tokens` appends token content as-is. The single-item sibling `Text.append` (and `Text.__init__`) runs `strip_control_codes` on string input; `rich/text.py` at base calls it at lines 155, 412 and 980, but not in `append_tokens`.
  - Content with a control character (`\r`, `\x07`) then makes wrapping raise `IndexError`.
- Gold: `rich/text.py`, +1 line: `content = strip_control_codes(content)` in `append_tokens`.
- FAIL_TO_PASS (1): `tests/test_text.py::test_append_tokens`. It builds `Text().append_tokens([("long text that will be wrapped with a control code \r\n", "red")])`, prints it at width 40, and asserts the exact wrapped output.
- PASS_TO_PASS: 107.

## Constraints

- **Budget.** v12-b1024, v0-think and v13: 5 min and 40 calls. v5h2 and v7*: 70 calls.
- **What the issue gives.** The method name and "exception". It does not say which input raises.
- **The sibling shows the missing step (measured, `edge_sweep`).**
  - On inputs with `\r\n` or `\x07`, `Text.append(s, "red")` renders fine, but `Text().append_tokens([(s, "red")])` raises `IndexError` at base.
  - The same happens on all three submitted box patches.
  - Plain text and a tab render fine through both.
  - Gold makes both render.
- **Gold in a clean environment: passes** (108 passed). It also passes with Pygments 2.21.0 and with the ipython lexers.
- **Test cost (indicative, bounded):** `tests/test_text.py` 0.60 s, F2P 0.57 s, install 0.93 s.

## Root cause

- **Taxonomy: UNDERSPECIFIED_ISSUE**, leading to **WRONG_SEMANTICS** (guarded the wrong input).
  - The issue names the method but not the input that raises.
  - The repository itself shows the missing step: the method's own single-item sibling sanitises control codes, and the bulk method does not.
  - The old diagnosis (UNDERSPECIFIED, no) is corrected to "maybe". The information is in the tree, one comparison away, and that comparison was measured.
- **Feasible in 5 minutes: maybe.**
  - The fix is 1 line, and the test takes 0.6 s.
  - v13 had already read both functions by 70 s.
  - 0 of 19 runs found it.

## SOLVE

- **Lever:** `submissions/v13_sibling_diff`, which is v13 plus one appended rule (commits 87610a09 and a3393270, the test wording fix).
  - If the function the issue names has a sibling that does the same job for a different input shape (one item and many, sync and async, str and bytes, load and loads), read both.
  - List the steps the sibling performs that the named one skips (cleaning, validation, copying, conversion).
  - Call both with the same unusual input (control characters, empty values, None), and port the missing step if only the named one fails.
  - The rule has no code fence and no tool-call-like syntax.
- **Offline evidence:** the `edge_sweep` above. The rule's own check, the same control-character input through both siblings, separates them at base and on every submitted patch, and gold passes it.
- **Tests:** `tests/test_v13_sibling_diff.py`, 5 tests, green. They cover:
  - the bundle differs from v13 only by the appended line;
  - no fence, tool syntax or braces;
  - leakage;
  - `scripts/validate.py`.
- **Outside the 42:** fastapi_5077 (contested). Its failing runs changed only one of two parallel code paths (the old diagnosis: "changed only get_typed_signature (1 of 2 hunks)"). Comparing the two paths is the same check (inferred).
