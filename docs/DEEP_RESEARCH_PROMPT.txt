aDEEP RESEARCH BRIEF: Kaggle "Google – The Gemma 4 Developer Agent Competition"
Written 2026-10-05. Please return live, sourced findings (links + dates), not general advice.

====================================================================================================
1. WHAT WE ARE BUILDING (context you need)
====================================================================================================
- Competition: Kaggle "gemma-4-developer-agent" (main track, $65k, final deadline 2026-12-02, team merge 2026-11-25)
  and the paper track "gemma-4-developer-agent-paper" ($35k, deadline 2026-11-12).
- Task: an offline coding agent that fixes GitHub-style issues (SWE-bench style). It is graded on ~120 HIDDEN tasks
  from PRIVATE repositories (public leaderboard = 58 of them, private = the rest). A task counts as solved only if all
  hidden FAIL_TO_PASS and PASS_TO_PASS tests pass after the agent's patch.
- Fixed model: google/gemma-4-31b-it, int4 QAT (W4A16, compressed-tensors), served by vLLM 0.19.1 on 4x NVIDIA L4
  (tensor-parallel 4), ~30 tokens/s decode, 32k context, events compaction at 14,336 tokens. No internet at run time.
- Submission = an ADK (Google Agent Development Kit) "agent config" bundle: agent.yaml + prompts + sub-agents
  (SequentialAgent/ParallelAgent/LoopAgent allowed) + "skills" (our own stdlib-only Python scripts run inside the
  sandbox) + optional LoRA adapters (rank <= 128, <= 3 GiB, loaded by vLLM). No custom ADK callbacks (the scorer
  registers none). Sampling knobs available: temperature, top_p, top_k, presence/frequency penalty, seed,
  max_output_tokens, thinking on/off.
- Tools the agent gets: run_command (5,000-char output cap, 300 s), read_file (150 lines), edit_file, write_file,
  submit_patch, get_status, code-graph tools (get_code_neighbors, search_similar_code, get_code_subgraph),
  run_skill_script, load_skill_resource.
- Budget per task: ~5 minutes wall clock and <= 70 tool calls (our eval_config); whole hidden run must finish in 12 h
  sequentially or the submission errors.
- One submission per day; two final selections.

====================================================================================================
2. WHERE WE ARE (measured, so you can judge what would be new to us)
====================================================================================================
- Public leaderboard: leader 0.24 (~14/58 tasks, team "ТониСтарк собрал реактор в яме", no public code); five teams
  at 0.17; most at 0.10-0.15. Our hidden reads: 0.10 (v4h2), 0.12 x2 (old scorer), 0.05 (v4 on the rebuilt scorer).
- Our best measured on the 74 locally-valid public tasks (faithful 4xL4 Kaggle run): 34/74 (v4h2g).
- Our agent today: 3 stages (locator -> fixer -> verifier), each with fresh context; our own stdlib helpers:
  locate.py (BM25/AST symbol search), edit.py (SEARCH/REPLACE edits with fuzzy matching and syntax rollback),
  test.py (targeted pytest runner), check.py (preflight: revert test edits, remove scratch), view.py (line viewer that
  refuses exact repeat reads).
- Failure profile of our 40 misses: 22 are "unreachable from the issue text" (title-only PR descriptions whose spec is
  behind a GitHub link, or hidden tests that check details the issue never states); 16 show repetition loops (the
  model repeats one identical tool call 10-74 times, often a read with a malformed argument); ~29 edit the right file
  with a wrong fix; 7 edit the wrong file; the 70-call budget binds more often than the 5-minute cap.
- Tried and ruled out (don't re-suggest without new evidence): bash-only scaffolds; heavy multi-stage pipelines with
  repair loops (scored lower: 0.08); thinking-on at large budgets (too slow); LoRA trained naively on our own
  successful trajectories (adapter applied but caused a read_file repeat loop, 0/5 on smoke); presence/frequency
  penalties as loop breakers (vLLM applies them within one completion only).
- Queued, not yet measured: temperature 0.2 (every scored public bundle uses 0.1-0.2), reproduction-script step,
  sibling-function sweep, rebalanced LoRA (v11b), and "v5all" combining all of these.
